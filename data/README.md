# Data Notes and Assumption Register

## Current Source

This version uses transparent illustrative demand distributions rather than proprietary company data. The case is an ecommerce fulfilment centre replenishing one generic non-perishable SKU from a nearby central warehouse. The product category is intentionally unspecified. The numbers form a controlled teaching scenario and must not be presented as observations from a named retailer.

The source of truth for all executable baseline assumptions is [`../outputs/model_assumptions.json`](../outputs/model_assumptions.json), generated by `python3 src/inventory_model.py`.

## Baseline Demand Distribution

| Daily demand units | Probability |
| ---: | ---: |
| 0 | 0.05 |
| 1 | 0.10 |
| 2 | 0.20 |
| 3 | 0.25 |
| 4 | 0.20 |
| 5 | 0.12 |
| 6 | 0.08 |

The expected daily demand is `3.13` units. Demand is assumed to be independent and identically distributed from one day to the next. This creates a finite, auditable state-transition model, but it does not capture weekly seasonality, promotions, or trends.

## Alternative Demand Distributions

| Scenario | Mean | Variance | Interpretation |
| --- | ---: | ---: | --- |
| Baseline mixed | 3.13 | 2.43 | Original moderate-demand case |
| Steady | 3.00 | 0.90 | Demand concentrated around three units |
| Volatile | 3.00 | 4.60 | Same mean as steady demand, with greater tail risk |
| Promotion peak | 4.79 | 3.07 | Higher average demand with values up to eight units |

The full probability vectors are generated in `outputs/model_assumptions.json`. These scenarios are not observed product segments. They are controlled experiments for testing how distributional shape changes cost and service decisions.

## Operational Scope

- One generic non-perishable SKU with no asserted product category.
- Daily inventory review.
- Same-day transfer from a nearby central warehouse, represented as zero lead time.
- Lost sales when demand exceeds available stock.
- No capacity, budget, or minimum-order constraint.

## Why the baseline is synthetic

The aim of the first study is methodological control. Every demand probability and cost parameter is visible, which makes the transition matrix, stationary result, simulation check, and sensitivity analysis auditable. A public transaction dataset would add empirical relevance, but it would also introduce product selection, returns, missing dates, outliers, aggregation choices, and licensing questions. Those belong in the next research stage rather than being hidden inside the baseline.

## Data Governance

No personal, client, transaction, or proprietary data is stored in this repository. Any future dataset should have a clear licence, be documented in this folder, and be processed through a reproducible script rather than manual spreadsheet edits.

## Extension Path

1. Use an openly licensed retail dataset and aggregate sales to daily demand.
2. Estimate and compare an empirical, Poisson, or seasonal demand distribution.
3. Add non-zero supplier lead time and outstanding-order states.
4. Replace the illustrative `97%` target with a service requirement agreed for the selected product and business.
