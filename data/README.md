# Data Notes and Assumption Register

## Current Source

This version uses a transparent illustrative demand distribution rather than proprietary company data. The case is a UK ecommerce fulfilment centre replenishing one standard USB-C charging cable SKU from a nearby central warehouse. The product context is concrete, but the numbers are still a controlled teaching scenario and must not be presented as observations from a named retailer.

The source of truth for all executable baseline assumptions is [`../outputs/model_assumptions.json`](../outputs/model_assumptions.json), generated by `python3 src/inventory_model.py`.

## Baseline Demand Distribution

| Daily demand units | Probability |
| ---: | ---: |
| 0 | 0.05 |
| 1 | 0.10 |
| 2 | 0.20 |
| 3 | 0.25 |
| 4 | 0.20 |
| 5 | 0.12 |
| 6 | 0.08 |

The expected daily demand is `3.12` units. Demand is assumed to be independent and identically distributed from one day to the next. This creates a finite, auditable state-transition model, but it does not capture weekly seasonality, promotions, or trends.

## Operational Scope

- One non-perishable consumer-electronics accessory: a standard USB-C charging cable.
- Daily inventory review.
- Same-day transfer from a nearby central warehouse, represented as zero lead time.
- Lost sales when demand exceeds available stock.
- No capacity, budget, or minimum-order constraint.

## Why the baseline is synthetic

The aim of the first study is methodological control. Every demand probability and cost parameter is visible, which makes the transition matrix, exact stationary result, simulation check, and sensitivity analysis auditable. A public transaction dataset would add empirical relevance, but it would also introduce product selection, returns, missing dates, outliers, aggregation choices, and licensing questions. Those belong in the next research stage rather than being hidden inside the baseline.

## Data Governance

No personal, client, transaction, or proprietary data is stored in this repository. Any future dataset should have a clear licence, be documented in this folder, and be processed through a reproducible script rather than manual spreadsheet edits.

## Extension Path

1. Use an openly licensed retail dataset and aggregate sales to daily demand.
2. Estimate and compare an empirical, Poisson, or seasonal demand distribution.
3. Add non-zero supplier lead time and outstanding-order states.
4. Compare the empirical result with the current `97%` service-constrained baseline.
